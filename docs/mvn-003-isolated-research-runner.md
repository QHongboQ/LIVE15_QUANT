# MVN-003 isolated research runner

`live15-research-preflight` is a bounded, single-process runner for future research only. It is
not a trainer, model promoter, runtime service, or production write path.

Its only approved input is a typed `ResearchUniverseSnapshot` plus a
`CanonicalEvidenceSnapshot`, serialized as a payload-free input envelope. The runner validates
`training_preflight` before any work unit is accepted. Dataset paths, frozen holdout payloads,
Recorder stores, and live runtime paths are rejected.

Create a separate environment outside the repository and outside `data/` or `runtime/`:

```powershell
scripts\bootstrap_research_env.ps1 -ResearchRoot D:\LIVE15_RESEARCH -Python313 C:\Path\python.exe
```

The command writes only beneath the explicit output root:

```text
<output>/experiments/<experiment-id>/{manifest.json,checkpoints,current.json,artifacts,metrics,logs}
```

Example smoke invocation (the snapshot must be generated by a typed RDA caller):

```text
live15-research-preflight --snapshot D:\LIVE15_RESEARCH\input.json --experiment mvn003-smoke --output D:\LIVE15_RESEARCH\output --checkpoint D:\LIVE15_RESEARCH\output\experiments\mvn003-smoke\checkpoints\current.json --code-revision <git-sha> --smoke-units 1
```

An experiment identity binds its ID, Research Universe ID/hash, canonical evidence ID, code
revision, resource config hash, adapter specification hash, and random seed. A different input,
configuration, code revision, or adapter cannot resume the same ID. Checkpoints are checksummed
JSON, written with fsync and atomic rename after every bounded interval. Completion, malformed
state, a live local lease, and output-root violations fail closed.

The runner deliberately uses one worker. `max_work_units`, `max_wall_seconds`, and
`max_output_bytes` are hard guards. `max_memory_bytes` guards Python-traced heap allocations; it
does not claim to cap native library allocations. Adding distributed training or a model family is
a later, separately reviewed task.
